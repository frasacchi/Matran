# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Matran is a MATLAB toolbox (developed in R2022a) for importing/visualising MSC.Nastran bulk data and results, and for writing `.bdf` files. All code lives in the `mni` package under `tbx/+mni` — add `tbx` to the path (or install via MATLAB Package Manager: `mpm install ... -e`). Everything is referenced as `mni.<subpkg>.<Name>`.

Matran is a dependency of sibling repos (`ads`, `baff`, `flexcast`, `tangle`, `Laca_update`, ...), which mostly call `mni.printing.cards.*` constructors and `mni.result.*` readers. Keep public signatures backward compatible — add new card fields as optional name-value args (see `PSHELL` `TST`/`NSM`).

## Tests

Tests are a single `matlab.unittest` class, `unit_testing/TestMatran.m`. Runner scripts in `unit_testing/` (README mentions `add_sandbox`, which no longer exists — just add `tbx` to the path):

```
matlab -batch "addpath(fullfile('..','tbx')); run_micro_tests"   % run from unit_testing/: dynamicable/bulk/obj/collector tests
run_short_tests     % import tests excluding large files, plus micro tests
run_all_tests       % everything (slow)
runtests('TestMatran/collector_add_item')   % single test method
```

QRG validation and round-trip suites (add `tbx` and `unit_testing/qrg` to the path):

```
runtests({'TestQrgBulkLayout','TestQrgBulkExamples','TestQrgCustomCards','TestBdfReader','TestQrgPrinting'})  % from unit_testing/qrg
runtests('unit_testing/TestRoundTrip.m')   % needs baff + ADS on the path; Nastran part skipped without MSC Nastran
printFailures(r)                            % readable diagnostics (unit_testing/qrg)
```

Caveats:
- `TestMatran` reads h5 test files from the sibling folder `../Matran_test_data` (not committed); without it the h5 tests are skipped by assumption. Legacy `obj_*` micro tests construct `mni.result.f06/hdf5` without arguments, which opens `uigetfile` and errors in batch mode (pre-existing).
- TPL import tests need `setpref('matran','PathToNastranTPL',<MSC tpl dir>)` (found automatically under `C:\Program Files\MSC.Software\MSC_Nastran_Documentation\*\tpl`).
- The QRG specs (`unit_testing/qrg/spec/*.json`) are generated by `tools/qrg/extract_qrg.py` from the QRG PDF (untracked, `.gitignore`d).
- `unit_testing/models/` is gitignored.
- The local MATLAB startup auto-adds an mpm "dev" collection (Matran, ads, baff, ...) to the path.

There is no lint/build step. Examples in `Examples/` (run from their own folder, they use relative `data/` paths) are the quickest smoke test for import + plotting.

## Architecture

Three largely independent subsystems, plus the bdf → baff converter and its validation harness:

### 1. Import & model (`mni.import_matran`, `+io`, `+analysis`, `+bulk`, `+mixin`, `private/`)
- `[fem, info, baffModel] = mni.import_matran(file, 'ToBaff', true)` dispatches on extension: `.bdf/.dat/.pch` → `private/importBulkData.m`, `.h5` → `private/importH5.m`. Then calls `makeIndices(FEModel)` to link objects, and `processResultsData` if results were also loaded. `info` (`mni.analysis.buildInfo`) holds SOL, subcases with every Case Control selection resolved to its bulk entries, PARAM/MDLPRM and a table of every entry (`info.Cards`).
- Reading: `mni.io.readDeck` (sections, INCLUDE tree relative to the including file) → `mni.io.tokenizeBulk` (QRG field rules: small/large/free field, continuations, replication, Nastran reals) → `mni.io.parseExecControl` / `parseCaseControl`.
- `importBulkData` maps each card name to a class via `private/isMatranClass.m`: first tries `mni.bulk.<Capitalised cardname>`, else looks up `private/defineBulkMask.m`, which is **built from the `addBulkDataSet` calls of the `mni.bulk` constructors** (e.g. `CBAR`/`CBEAM`/`CROD` → `mni.bulk.Beam`). **Supporting a new card for import = add/extend a `mni.bulk` class** (and a QRG test). Entries without a class are kept as text by `mni.bulk.GenericCard` (nothing is skipped).
- Field layouts must match the QRG: blanks are `'b'` in `PropTypes`; `unit_testing/qrg/TestQrgBulkLayout` checks every class against `spec/qrg_bulk.json`. Cards with keyword lines or variable streams (PBEAM, PBUSH, RBE2/3, DMI, PCOMP, ...) have dedicated parsers (`TestQrgCustomCards`).
- `mni.bulk.BulkData` is the base class. One object holds *all* cards of one type in vectorised form (columns = entries). Each subclass constructor calls `addBulkDataSet(obj, 'CARD', 'BulkProps', ..., 'PropTypes', ..., 'PropDefault', ..., 'IDProp', ..., 'PropMask', ..., 'Connections', ..., 'AttrList', ..., 'SetMethod', ...)` once per supported card name; properties are created as **dynamic properties** (`mni.mixin.Dynamicable`) for whichever card is active. `PropTypes` chars: `i` int, `r` real, `c` char, `b` blank (blank has no prop/default). `PropMask` collapses consecutive fields into one multi-row prop (e.g. `GA_GB`,2). `Connections` drive `makeIndices` linking (e.g. beam → `mni.bulk.Node`). Subclasses override `assignH5BulkData` for HDF5 import.
- `mni.bulk.FEModel` is a `mni.mixin.Collector`: each bulk object is added as a dynamic property named by card, so `model.GRID`, `model.CAERO1`, etc. It also owns `draw`/`update`/`animate` (interactive figure callbacks).

### 2. Results (`+result`)
Old-style `@folder` classes; each reader method is its own file:
- `mni.result.f06(path).read_*` — parses text `.f06`.
- `mni.result.hdf5(path).read_*` — reads MSC HDF5 output. Several readers intentionally return the same struct layout as f06 equivalents (e.g. `read_flutter_summary` ≙ f06 `read_flutter`).
- `mni.result.op4` — matrix files.
Results are typically applied to a model manually (e.g. `model.GRID.Deformation = ...; model.update`) — see `Examples/`.

### 3. Writing bdf (`+printing`)
Independent from `+bulk` (no shared classes). Each card in `+printing/+cards` subclasses `BaseCard` (`matlab.mixin.Heterogeneous`, so mixed cards can be stored in one array):
- Constructor uses an `arguments` block; required fields positional, optional ones as `opts.X` name-value pairs. Set `obj.Name = 'CARD'`.
- `writeToFile(obj, fid, varargin)` calls `writeToFile@mni.printing.cards.BaseCard(...)` (optional comment) then `obj.fprint_nas(fid, format, data)`.
- `fprint_nas` format string: `s` string, `i` int, `f`/`r` real, `b` blank column, `n` force new line. Empty/NaN values print blank. It handles 8/16-char columns (`LongFormat`) and continuation lines automatically; reals go through `num2nasSFFstr`.
- `+printing/+bdf` has helpers for comments/headings/file stamps; `+printing/+cases` for case-control entries.
- `unit_testing/qrg/TestQrgPrinting` prints a fixture of each card ADS writes and checks every value sits in its QRG field (small and large field).

### 4. bdf → baff (`+baff`, `+util/Geometry.m`)
- `mni.baff.fromFEModel(fem, info)` (or `import_matran(..., 'ToBaff', true)`) builds a `baff.Model` from the bulk data only: beam chains → `baff.Beam`/`baff.Wing`, CQUAD4 surfaces → shell `baff.Wing`, CAERO1 → aero stations / control surfaces, CONM1/2 → `baff.Mass`, SPC set → `baff.Constraint`, RJOINT/CBUSH → `baff.Hinge`. `info.Baff` is the conversion report (components, notes on every approximation, dropped items, aero mesh, loads).
- `private/`: `collectModel` (bulk → plain structs), `analyseStructure` (components, rigid clusters, tree links, satellites), `aeroData` / `aeroStations` (inverse of the ADS CAERO1 placement).
- `mni.bulk.beamSection` gives PBARL/PBEAML A, I1, I2, I12, J (verified against Nastran; QRG figure axes: horizontal = z_elem).

### 5. Validation (`+validation`)
- `mni.validation.roundTrip(file)`: bdf → Matran → baff → ADS (`ads.baff.baff2fe`) → `rt_model.bdf`, `compareModels`, then MSC Nastran SOL 103 (GPWG, frequencies, MAC) and SOL 101 on both models; `report.md` in `validation/results/<Name>/` (gitignored). Needs the sibling repos `baff` and `ads` on the path.
- Status, decisions and findings: `docs/bdf2baff/PROGRESS.md`.
